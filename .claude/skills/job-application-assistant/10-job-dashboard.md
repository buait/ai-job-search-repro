# 求职战况仪表盘（Job Dashboard）

求职是一场需要持续复盘的马拉松。只埋头投简历而不看数据，很容易在低效渠道上浪费大量时间。本技能定义了一套"战况复盘"方法论：定期把申请记录、岗位轨迹和薪资行情汇总成一张中文战报，用漏斗数据驱动下一步行动。

---

## 核心概念

### 申请漏斗（Application Funnel）

把申请过程看作一个漏斗，越往下越接近录用：

| 阶段 | 含义 |
| --- | --- |
| 已投递 | 简历已提交，尚无回音 |
| 进行中 | 进入筛选/评估流程 |
| 面试中 | 正在进行一轮或多轮面试 |
| 已获 Offer | 收到录用意向 |
| 已接受 | 接受 Offer 并入职/待入职 |
| 已拒绝 | 收到拒绝通知 |
| 已撤回 | 主动放弃申请 |
| 无回音 | 长期无回应（可能被默默淘汰） |

**复盘要点**：对比相邻两阶段的转化率。如果"已投递 → 面试中"转化率低，问题多半在简历与岗位的匹配度；如果"面试中 → Offer"转化率低，问题多半在面试表现。

### 三个数据源

1. **申请记录**：`documents/applications/*.md`，每份文件对应一家公司的申请，记录公司、状态、日期、渠道。
2. **岗位轨迹**：`job_scraper/seen_jobs.json`，记录历次抓取见过的岗位，反映市场覆盖面。
3. **薪资行情**：`salary_data.json`，用户维护的薪资基准数据，用于谈薪对标。

## 操作流程

1. **生成战报**：运行 `python3 tools/dashboard_state.py`（或由 `/dashboard` 命令编排）。
2. **读漏斗**：先看累计申请、面试中、Offer、被拒四个数字，判断当前阶段。
3. **看分布**：状态分布找异常（如无回音过多）、渠道分布找最优渠道。
4. **给建议**：基于规则给出方向性建议，结合用户目标行业/城市细化。

## 复盘建议规则（工具内置）

- 申请 ≥3 且 0 面试：建议检查简历与目标岗位匹配度。
- 有面试但 0 Offer：建议用 `/interview` 做针对性准备并逐场复盘。
- 被拒占比 >60%：建议收缩投递范围，集中投更匹配的岗位。
- 面试转化率 <20%：建议优化简历关键词与项目经历描述。

## 约定

- 战报**只汇总、不评判单个申请**；具体岗位的评估仍走 `/apply` 流程。
- 数据缺失时如实标注 N/A，**禁止编造**申请记录或数据。
- 战报语言固定为中文，方便求职者快速阅读。
