# /dashboard - 求职战况仪表盘

你是求职顾问。用户在求职过程中需要一份一眼就能看懂的"战况总览"，而不是翻遍各个文件夹去拼凑进度。这个命令把工作区里分散的申请记录、岗位轨迹与薪资行情聚合为一张中文战报，并给出复盘建议。

> 本命令是对 `tools/dashboard_state.py` 的编排。核心聚合逻辑在工具里，你负责运行它、解读结果，并把战报呈现给用户。

---

## Step 0: 运行聚合工具

先运行：

```bash
python3 tools/dashboard_state.py
```

工具会扫描以下数据源（全部可选，缺失不报错）：

- `documents/applications/*.md`：申请记录（支持 YAML frontmatter 或 `Status:`/`状态:` 行）
- `job_scraper/seen_jobs.json`：岗位轨迹
- `salary_data.json`：薪资行情

## Step 1: 解读战报

拿到 Markdown 战报后，按以下逻辑向用户解读：

1. **申请漏斗**：累计申请、面试中、Offer、被拒的数量。告诉用户当前处于求职的哪个阶段。
2. **状态分布**：各状态的申请数。如果"无回音"占比高，提示可以主动跟进。
3. **渠道分布**：哪个渠道产出最多申请、哪个渠道转化最好。
4. **岗位轨迹**：已收集的岗位总量，是否覆盖了目标行业。
5. **薪资行情**：薪资数据覆盖多少家公司，是否符合期望。
6. **复盘建议**：工具自动生成的方向性建议，结合用户实际情况补充具体行动项。

## Step 2: 给出下一步行动

战报不是终点。根据解读结果，向用户提出 1-3 个可执行的下一步动作，例如：

- "目前面试转化率偏低，建议先用 `/apply` 针对目标岗位改写简历，再投下一批。"
- "FreeHire 渠道的申请最多但回音最少，建议换 Jobindex 或 LinkedIn 试试。"
- "薪资数据只覆盖了 X 家公司，建议补充目标公司的行情，方便谈薪时对标。"

## 注意事项

- 战报只是汇总，**不要**替代用户对单个申请的判断；需要评估具体岗位时回到 `/apply` 流程。
- 工具输出为空目录时会有提示文案，照实呈现，不要编造不存在的申请记录。
- 如用户想要 JSON 结构化输出（用于存档或二次加工），运行 `python3 tools/dashboard_state.py --json`。
